# Changelog

All notable changes to AgentRisk are documented here. The format follows
[Keep a Changelog](https://keepachangelog.com/), and the project uses
[Semantic Versioning](https://semver.org/).

## [Unreleased]

### Added
- Initial implementation of the three core tools:
  - `analyze_portfolio_risk`: concentration report, exposure breakdowns
    (sector / asset class / theme), HHI concentration score, top risks, and a
    policy-compliance audit, with a focus spotlight for targeted questions.
  - `check_trade_risk`: pre-execution validator returning `PASS` / `WARN` / `BLOCK`
    with a `proceed` boolean, per-check detail, and a templated summary. Checks:
    single-name / sector / theme / asset-class concentration, asset-class rules
    (crypto / options / margin), order size, minimum cash, restricted symbols, and
    snapshot staleness.
  - One-time bypass: `check_trade_risk(override=[...])` lets a human approve a single
    blocked trade without editing the policy, returning an `OVERRIDDEN` verdict.
    Blocks are tiered (soft limits, hard prohibitions, non-overridable feasibility
    checks); every bypass is written to the audit log as a `trade_override` record.
  - `generate_risk_policy`: create / update / show a human-readable YAML policy,
    with a diff-and-confirm flow that classifies changes as tightening / loosening /
    neutral and archives prior revisions.
- Pure Python core (no network, no LLM, no API keys) plus a thin stdio MCP server.
- `agentrisk` command-line interface wrapping all three tools (`policy`, `check`,
  `analyze`) for shell and CI use. `check` exits non-zero on BLOCK so it composes in
  a shell pipeline.
- Bundled open classification taxonomy and a broad seed dataset: asset-class
  coverage for the full US-listed universe (public Nasdaq Trader directory) plus a
  hand-curated sector/theme overlay that always wins. Regenerated by
  `scripts/expand_seed.py`; `unverifiable_exposure` warns when a sector cap cannot be
  checked against a sector-unknown equity.
- Optional Agent Skill (`skills/agentrisk/SKILL.md`) that gates a Claude agent's
  trades: classify the proposal, call `check_trade_risk`, respect the verdict, and
  record the result before any order is placed.
- Claude Code plugin packaging (`.claude-plugin/` plus a plugin-root `.mcp.json`)
  with a single-plugin marketplace. Installing the plugin registers the MCP server
  via `uvx`, so the skill and the server arrive together with no separate install.
- Append-only JSONL audit log for verdicts and policy changes.
- Safety behaviors: fail closed (no policy means BLOCK), never trap exits, and only
  breach-worsening trades block.
- Test suite: unit, golden snapshots, property-based (hypothesis), seed-data lint,
  and MCP contract tests.

### Security
- A trade can no longer weaken a curated classification: declaring an `asset_class`
  that contradicts the bundled data for a known symbol (relabelling crypto as
  equity, say) is rejected as an invalid trade instead of skipping the rule.
- An `asset_class: option` trade must now carry its option detail; without it the
  order value was sized at multiplier 1. Missing detail fails closed to BLOCK.
- The margin asset rule now exempts reducing (sell) trades, matching crypto and
  options, so closing a leveraged position is never trapped.
- A policy file that exists but cannot be parsed fails closed with a generic
  message, so a caller-supplied `policy_path` cannot read file contents back
  through a parser error.
- A policy create or update that cannot be written to the audit log now fails
  closed and rolls back, rather than leaving an unaudited change in place.
- The bundled MCP configuration installs the server from the project's own
  repository instead of resolving an unpinned name from a package index.
