# Classification data

To answer questions like "how much AI exposure do I have?" AgentRisk needs to know
what each holding *is*. It resolves this without any network call.

## Resolution order

1. **Caller metadata wins.** Anything you set on a position (`asset_class`,
   `sector`, `tags`) is authoritative.
2. **Bundled seed data.** Otherwise AgentRisk consults its versioned dataset
   (`src/agentrisk/data/classifications.json`).
3. **Unclassified.** If neither knows, the instrument is reported as unclassified;
   it shows up in the `data_quality` section and in an `unclassified` bucket. It is
   never guessed.

## Two layers: a broad base and a curated overlay

The bundled dataset is built from two layers, merged into one shipped file:

- **Broad base (asset class + name).** Every US-listed symbol from the public
  Nasdaq Trader symbol directory is included as either `equity` or `etf`, with its
  security name. This is what makes it rare for a real ticker to be *fully* unknown.
  These entries carry `"source": "nasdaqtrader"` and a `null` sector.
- **Curated overlay (sector + theme tags).** A hand-maintained set adds sectors and
  theme tags for well-known instruments. These entries carry `"source": "curated"`
  and **always win** over the broad base.

What the broad base does not do: it does not invent sectors or theme tags. There is
no free, redistributable sector dataset (GICS is proprietary), and theme membership
is subjective. So a long-tail equity is known to be an equity but may have no sector
until someone curates it.

Because of this split, a sector or theme cap can only bind on instruments whose
sector or tags are curated. When you trade a sector-unknown equity while a sector cap
is set, `check_trade_risk` returns a WARN (`unverifiable_exposure`) rather than
silently ignoring the cap.

## The taxonomy is our own, and open

AgentRisk defines a small, redistributable taxonomy in
`src/agentrisk/data/taxonomy.json`: ~11 sectors and a curated set of theme tags
(`ai`, `semiconductors`, `ev`, `biotech`, `fintech`, `defense`, `energy-transition`,
`crypto`, `broad-market`).

It is deliberately **not GICS**, since GICS is proprietary and cannot be shipped with an
open-source project. This file is the transparent, reviewable source of truth, and you
can override any classification per position.

## Expanding the dataset

Broad asset-class coverage is regenerated by a build-time script (it runs only when
you choose to; the shipped library still makes no network calls):

```bash
python scripts/expand_seed.py --dry-run   # preview counts
python scripts/expand_seed.py             # fetch + merge, preserving curated entries
pytest tests/test_seed_data.py            # lint the result
```

The script pulls the current US-listed universe and adds any missing symbols. It
never overwrites a curated entry, so hand-added sectors and tags are preserved.

## Honest limitations

- Sectors and theme tags are curated, not exhaustive. A ticker can be a known equity
  yet have no sector until someone adds it.
- Classifications drift (companies pivot, ETFs rebalance, tickers change). Curated
  data is updated only by reviewed contribution, never at runtime.
- ETFs are treated as single positions in v1, with no look-through into their holdings
  (that's a v0.2 item), so "duplicated risk" via overlapping funds isn't detected yet.

## Contributing a classification

Open an issue with the **Add or correct an instrument** form, or send a PR editing
`src/agentrisk/data/classifications.json`. Each entry needs a valid `asset_class`, a
`sector` that exists in the taxonomy (or `null`), `tags` drawn from the taxonomy, and
a `source`. The CI lint in `tests/test_seed_data.py` enforces all of this. Theme tags
are subjective, so include a brief rationale.
